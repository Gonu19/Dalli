# DEMO.md — 시연 대본 90초

## 전제
- **무대에서 라이브 러닝 시연은 하지 않는다.** 90초 서사는 **사전 촬영 영상**으로 보여준다
- **촬영 소스는 실제 야외 러닝이다.** 실기기 화면녹화 + 러닝 인서트 컷
- 8/19 야외 검증(D6)과 촬영을 같은 러닝에서 겸한다 — 어차피 뛰어야 한다
- 시나리오는 저절로 나오지 않는다. **뛰는 사람이 초반에 의도적으로 빠르게 나갔다가
  후반에 처져야** 한다. 하향은 `5분 이후 + 실패 2회`라 최소 8분 이상 걸리므로
  20분 러닝으로 잡고 한 번에 안 나올 것을 전제로 여유를 둔다
- 야외 촬영이 실패하면(우천·백그라운드 사망·업로드 오류) 대안이 없다.
  `ROADMAP.md` §6의 시뮬레이션 폴백을 쓰려면 진입점이 먼저 있어야 한다
- `seed.py`로 과거 기록 7~10일치 + 캘린더 계획 미리 생성
- 촬영 시 외부 음악 앱(스포티파이 등) 재생 중 상태 ← **차별점 시각화**
- **리커버리 모드는 시연에 넣지 않는다.** 90초 안에 하향까지가 서사의 끝이고,
  리커버리는 "앱이 조용해지는" 동작이라 화면상 보여줄 것이 없다

## ⚠️ 시나리오 — `TOO_FAST`는 하향으로 이어지지 않는다

`ENGINE.md` §7에서 **`TOO_FAST`는 개입만 하고 downshift 경로가 없다.**
downshift는 `TOO_SLOW`·걷기에서만 발생한다.

따라서 *"초반 과속 → 회복 실패 → 목표 하향"*은 **엔진상 발생할 수 없는 시나리오**다.
러닝을 아래 흐름으로 만든다. 뛰는 사람이 이 순서를 의도적으로 만들어야 한다.

```
초반 과속           →  TOO_FAST 안내 (1회)
     ↓
잠시 안정            →  무음
     ↓
후반 리듬 저하        →  TOO_SLOW 안내
     ↓
쿨다운 후 미회복      →  실패 2회
     ↓
Downshift            →  "목표를 152로 낮췄어요"
     ↓
새 목표로 완주
```

서사도 이쪽이 더 자연스럽다 — **초반 과속이 후반 저하의 원인**이라는 인과가 화면에 그대로 보이고,
그게 리포트의 `hypothesis`("초반보다 빠른 리듬으로 시작한 영향일 수 있어요")와 정확히 이어진다.

## 대본
| 초 | 화면 | 멘트 |
| --- | --- | --- |
| 0–10 | 홈 | "초보 러너는 자기 페이스를 몰라 초반에 과속하고, 10분 뒤 걷습니다. 달리는 케이던스로 이걸 잡습니다." |
| 10–20 | 홈 (목표·컨디션 선택) | "오늘 20분, 컨디션은 보통. 제 기준 리듬은 **157**입니다." — **음악 재생 중임을 보여줌** |
| 20–30 | `/run/active` | "시작. 화면은 이제 안 봅니다. 리듬이 유지되면 앱은 아무 소리도 내지 않습니다." |
| 30–40 | **초반 과속** (`TOO_FAST`) | (음성 개입 재생) "리듬이 빨라지자 3초짜리 한 문장. 음악은 안 끊깁니다." — **숫자 색이 바뀌는 것**을 보여줌 |
| 40–48 | **후반 리듬 저하** (`TOO_SLOW`) | "10분이 지나자 리듬이 처집니다. 초반에 빠르게 나간 대가입니다." |
| 48–60 | **회복 실패 → 하향** | "안내 뒤에도 회복이 안 되면, 실제로 달리고 있는 리듬 기준으로 **목표를 152로 낮춥니다.** 실패가 아니라 조정입니다." |
| 60–75 | `/run/report` | "완주. **안정 구간 72%**, 오늘의 부담은 **보통**. AI가 한 줄 판정과 다음 러닝 처방 한 가지를 줍니다." |
| 75–90 | `/record` 캘린더 | "기록은 캘린더로 이어집니다. 앱 없이 뛴 날도 수기로 남습니다. 누적 10일 — 달리는 한 번의 운동을 루틴으로 만듭니다." |

## 강조 3가지
1. **Silent by default** — 범위 안에서는 무음. 외부 음악 안 끊김
2. **목표 하향** — 실패로 처리하지 않고 현실적 범위로 조정 (경쟁 앱과의 차이)
3. **루틴 연결** — 러닝 1회로 끝나지 않고 캘린더·수기 기록까지

## 촬영·리허설 체크리스트
- [ ] 러닝에서 **`TOO_FAST` 1회 → `TOO_SLOW` 2회(실패) → `TARGET_ADJUSTED` 1회**가 순서대로 발생했는가
- [ ] 한 번에 안 나오면 **다시 뛴다.** 편집으로 순서를 만들지 않는다 — 화면의 숫자가 어긋난다
- [ ] `TOO_SLOW`는 **5분(300초) 이후에만** 발동하므로 저하 구간을 그 뒤로 가져갔는가
- [ ] 하향 시 **중심값이 157 → 152로 바뀌는 게 화면에 보이는가** (범위 숫자는 안 나와야 함)
- [ ] 워밍업 90초는 무음이므로 **편집에서 잘라낸다**
- [ ] 음성 안내 구간은 **실시간 배속으로 남긴다** (빨리감기하면 알아들을 수 없음)
- [ ] AI 리포트 8초 타임아웃 → 폴백 문구가 정상 출력되는가 (**네트워크 죽어도 촬영 진행돼야 함**)
- [ ] 폴백일 때 가설·회복 안내 섹션이 **빈 카드로 남지 않는가**
- [ ] seed 데이터로 캘린더·분석 탭이 비어 보이지 않는가
- [ ] 기기 미러링 지연 확인, 오디오가 미러링에도 들리는가
- [ ] 배터리 50% 이상, 알림·방해금지 설정
- [ ] **프로비저닝 만료일 확인** (무료 계정 7일 — `ROADMAP.md` §1-1)
- [ ] 백업: 화면 녹화 준비 (라이브 실패 대비)
