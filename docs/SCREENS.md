**온보딩은 4단계다.** `experience → purpose → body → schedule` 뒤 기준 리듬으로 넘어간다.
`experience`의 `전체 건너뛰기`는 기본값(목적 `COMPLETE`)으로 곧장 `/onboarding/cadence`로 간다.

> 목적을 두 번 묻던 `/onboarding/reason`은 없앴다. `purpose`와 같은 5개 값을 라벨만 바꿔
> 다시 물었고, 그 답은 서버로도 엔진으로도 가지 않았다.

기본 탭 = 홈(가운데). 온보딩 미완료면 루트에서 `/onboarding`으로 redirect.
**앱 강제 종료 등으로 미완료 로컬 세션이 남아 있으면 끊긴 지점까지를 `completed: false`로 자동 저장하고 업로드 큐에 넣는다.** 끊긴 동안의 시간·걸음을 알 수 없어 지표가 왜곡되므로 세션을 이어서 재개하지 않는다. 3분 미만 조각은 분석 불가 기록이므로 복구하지 않는다.

## 화면 명세

### `/onboarding` · `/experience` · `/purpose` · `/schedule` 필수 입력
- `/onboarding` 시작 → `/experience`(1/4) 경험 수준·최대 연속 러닝 시간 →
  `/purpose`(2/4) 러닝 목적 → `/body`(3/4) 신체 정보 → `/schedule`(4/4) 주간 목표 횟수
- **러닝 목적은 한 번만 묻는다.** 완주 / 습관 형성 / 체중 관리 / 체력 향상 / 기록 향상
- 목적 화면에 **"케이던스 추천은 러닝 경험과 목적을 기준으로 해요"** 를 적는다.
  신체 정보를 건너뛰어도 추천에 영향이 없다는 근거다 (`ENGINE.md` §2)
- 진행바와 `n / N` 표시는 단계 수 하나(`ONBOARDING_STEP_COUNT`)를 본다.
  단계를 늘리거나 줄이면 그 값만 고친다
- API: 없음 (로컬 보관). 저장은 마지막 리듬 화면에서 한 번에

### `/onboarding/body` 신체 정보 — 전부 선택 입력
- 입력: **키(cm) · 몸무게(kg) · 출생연도 · 성별** (`users.height_cm`/`weight_kg`/`birth_year`/`gender`)
- **입력 전에 사용 목적과 처리 근거를 표시한다** (PRD §12, FR-003)
  - 문구 예: "칼로리 추정에 사용해요. 지금 건너뛰어도 되고, 나중에 설정에서 입력할 수 있어요."
- **`건너뛰기`가 항상 보인다.** 비워도 다음 단계로 진행되며 케이던스 추천에 영향이 없다
- 몸무게는 소수 1자리 허용(`62.5`), 나이는 **출생연도**로 받는다 (나이는 시간이 지나면 틀려진다)
- 다음 → `/onboarding/cadence`
- API: 없음 (로컬 보관 후 `/onboarding/cadence` 완료 시 일괄 전송)

> **케이던스 추천 로직에는 신체 정보를 쓰지 않는다** (`ENGINE.md` §2 — 경험 수준·목표만).
> 키·몸무게로 케이던스를 예측하는 건 근거가 약하다. 이 값들은 **칼로리 추정용 후속 자산**이며,
> 실제 칼로리 계산에는 `weight_kg`만 필요하다. 나머지는 지금 쓰이지 않는다.

### `/onboarding/cadence` 기준 리듬
- Rule-based 추천 baseline **중심값 1개** 표시 + **추천값 기준 ±10 spm, 절대 130~185**, 버튼 `−5 / −1 / +1 / +5`
- 안내: "첫 러닝에서 실제 리듬을 측정해 기준을 확정합니다"
- 완료 → `POST /auth/device` → `PATCH /users/me` → `/`

### `/` 홈
- 오늘의 목표: 시간 | 거리 토글 + 값
- 컨디션: 가벼움 / 보통 / 피곤함 → 서버 전송값 **5 / 3 / 1** (`ENGINE.md` §3)
- 안내 방식: 음성 on/off, 메트로놈 on/off
- **오늘의 리듬 = 중심값 1개만** 표시 (`오늘의 리듬 157`). 범위(min~max) 노출 금지 — `PRODUCT.md` §8-2
- **러닝 시작** 버튼 → `/run/active`
- 최근 러닝 요약 카드 / 누적 러닝 데이
- API: `GET /stats`, `GET /runs?limit=1`, `GET /plans?from=today&to=today`

### `/run/prepare` 러닝 준비
- 파라미터: `condition`(컨디션 3단계), `cadence`(기준 리듬)
- **목표 케이던스 조절** `-5 / − / + / +5`, 130~185로 제한
- **목표 리듬 미리듣기** — 카드 우상단 `들어보기`. 숫자만 보고는 160 spm이 어떤 빠르기인지
  알 수 없다. 메트로놈 설정이 꺼져 있어도 울린다 — 그 설정은 러닝 중 **자동** 개입을
  켜고 끄는 것이지 직접 누른 재생까지 막지 않는다. 리듬을 바꾸면 바뀐 박자로 다시 들려준다.
  같은 동작을 `/onboarding/adjust`도 쓴다 (`useMetronomePreview`)
- **목표는 시간/거리 중 택1.** 값 칸 왼쪽 `[시간|거리]` 토글로 고른다.
  시간 5~120분(5분 단위), 거리 1.0~15.0 km(0.5 km 단위)
  - 두 값을 각각 들고 있어 토글을 오가도 방금 고른 값이 남는다
  - 아직 값이 없는 쪽으로 바꾸면 기본값(30분 / 3.0 km)을 채운다. 빈 칸으로 두면 시작 버튼이
    잠긴 채 이유를 알 수 없다
  - 오늘 계획이 있으면 그 목표로 채우고 `「제목」 목표예요.`를 표시한다.
    **계획이 거리 목표여도 시간으로 덮어써지지 않는다**
- 러닝 가이드 방식 토글 3개: 음성 안내 · 메트로놈 비트 · 진동 알림

### `/run/active` 러닝 중
**화면 안 보고 뛰는 화면** — 큰 숫자, 고대비, 큰 터치 영역.
- 경과 시간(대), **현재 리듬(대)**, **오늘의 리듬 = 중심값 1개**, 거리·페이스(GPS 없으면 `—`)
- Apple Maps 지도에 현재 위치와 지나온 경로를 표시한다. 경로선은 러닝 중 메모리의 `getRoutePath()`를 사용하며 GPS 미수신 시 빈 지도를 유지한다.
- **범위 안/밖은 숫자가 아니라 현재 리듬 숫자의 색으로 표현한다.**
  정확히 157을 맞추는 건 불가능하므로 "틀렸다"는 인상을 주면 안 된다 (`PRODUCT.md` §8-2)
- 컨트롤: 일시정지·재개, 종료
- 상태 소스: `store/runStore`의 `RunState`만 구독. 엔진 내부 접근 금지.
- 종료 → **종료 확인 시트** → 업로드(`POST /runs`) → `/run/finish`

| RunState | 화면 |
| --- | --- |
| `RUNNING` | 기본 |
| `PAUSED` | 딤 + 재개 버튼 |

> **`CALIBRATING` 화면은 없다.** 첫 러닝도 다른 러닝과 동일하게 `RUNNING`으로 시작한다.
> 실측 baseline은 종료 후 `samples`에서 산출해 리포트에서 확정한다 (`ENGINE.md` §2).

| 판정 상태 | 화면 표시 |
| --- | --- |
| 워밍업(0~90초) | **배지 없음.** 워밍업이라는 개념을 노출하지 않는다 (`PRODUCT.md` §8-2) |
| 범위 안 | 리듬 숫자 기본색 |
| 범위 밖 | 리듬 숫자 강조색 |
| `UNAVAILABLE` | 리듬 자리에 `—` + "측정이 어려워요". **빠름/느림 판정을 표시하지 않는다** |
| 목표 하향됨 | "목표를 152로 낮췄어요" 토스트 1회 + 중심값 갱신 |
| 리커버리 | "지금은 회복이 우선이에요" 1회. 이후 **어떤 안내도 뜨지 않는다** |

#### 종료 확인 시트 (FR-011)
`취소`(러닝 계속) / `종료하고 저장` / `기록 버리기` 3분기.
- 버튼 **1회로 삭제되지 않는다**
- `기록 버리기`는 파괴적 결과를 한 번 더 명시하고 재확인

### `/run/finish` 완료 → `/run/image` 결과 이미지
- 저장 상태와 완주/중도 종료 요약
- **카메라 촬영 또는 갤러리에서 사진 선택**(`expo-image-picker`) → 9:16 배경 합성
- 카메라·사진 권한 거부 시 기능 영향과 설정 이동을 안내하고, 취소해도 완료 기록은 유지
- 활동 시간 · 거리 · 평균 리듬 · **평균 페이스** · **경로**는 각각 결과 이미지 포함/제외를 고르는 토글이다. 기본은 모두 포함이며, 선택 해제한 항목은 미리보기·저장 이미지 모두에서 제외한다. 경로는 러닝 중 화면과 동일한 `getRoutePath()`를 사용한다.
- **경로는 한 붓 곡선 하나로 그린다.** 선분을 이어 붙이면 꺾이는 자리마다 틈이 생겨 코스가 끊겨 보인다. 점을 솎고 이웃 평균으로 떨림을 누른 뒤 곡선으로 잇는다 (`run-map.tsx`).
- 라벨은 `평균 리듬`이다. `평균 케이던스`로 쓰지 않는다 (`PRODUCT.md` §8-1).
- `react-native-view-shot`으로 9:16 결과 카드 전체를 캡처해 이미지로 저장한다.
- `이미지 저장` → 기기 보관 / `리포트 보기` → `/run/report`
- **권한 거부·취소·저장 실패에도 러닝과 리포트는 유지된다.** 건너뛰기로 리포트 이동 가능

### `/run/report` 종료 리포트
- 기본: 목표 vs 실제, 완주 여부, **안정 구간(%)**, 평균 리듬·페이스, **변화 그래프**
- **변화 그래프**는 꺾은선 한 판에 겹쳐 그린다. 아래 `리듬 변화` / `페이스 변화` / `안정 구간 변화`
  버튼으로 켜고 끄며 여러 개를 동시에 볼 수 있다. **마지막 하나는 끌 수 없다** (빈 카드 금지).
  하나만 켜면 값 눈금과 면 채우기가 나온다 — 단위가 다른 선이 겹친 상태에서는 눈금을 그리지 않는다.
  안정 구간에는 러닝 전체 값(`rhythm_score`)을 가로 점선으로 겹쳐 `러닝 전체 NN%`로 적는다.
- **첫 러닝에서는 "기준 리듬을 찾았어요 — 157"을 먼저 보여준다** (`ENGINE.md` §2)
- AI: 한 줄 판정 → **근거 1~3개** → 가능한 원인(가설) → 다음 처방 → 다음 목표 → **회복 안내**
- `limitation`이 채워져 있으면 **그 문구를 그대로 표시**한다 (GPS 미수신·6분 미만·센서 부족)
- **분석 제한이 있어도 리포트는 만든다.** 앱이 미리 막지 않는다. 서버는 `is_analyzable`이
  false면 LLM만 건너뛰고 규칙 기반 폴백을 201로 돌려준다 (`services/reports.py`).
  짧은 러닝에서도 한줄평·다음 목표·다음 러닝 예약까지 이어진다.
  **수기 러닝만 예외** — 서버가 422로 거부하므로 앱에서도 요청하지 않는다.
- AI 로딩 스켈레톤(최대 8초). 실패/타임아웃 시 폴백 문구 그대로 표시, **에러 화면 금지**
- 폴백일 때 `hypothesis`·`recovery_note`는 `null`이므로 **해당 섹션을 그리지 않는다** (빈 카드 금지)
- API: `POST /runs/{run_id}/report`
- 닫기 → `/analysis`

**피로도는 소수를 노출하지 않는다.** `여유로움`(< 0.35) / `보통` / `부담됨`(≥ 0.6) 3단계 라벨.

### `/run/ai` AI 상세 리포트
- 한 줄 판정 → 피로도 지수 → 분석 근거 → 가능한 원인 → 다음 러닝 제안 → 회복 안내 → 다음 목표
- 폴백이면 `기본 분석`으로 표시하고, `hypothesis`·`recovery_note`가 `null`인 섹션은 그리지 않는다

#### 다음 러닝 예약
`다음 목표` 아래 `이 목표로 다음 러닝 예약하기` 버튼 하나. **새 화면으로 가지 않는다.**
- 확인 시트 3줄 — 날짜 `[−1일][+1일]` / 목표 거리 `[−0.5][+0.5]` / **목표 리듬(조절 불가)**
- 날짜는 AI가 아니라 **피로도로 정한다.** 주간 목표 횟수로 기본 간격을 잡고, 부담이 크면
  하루 더 민다. 부담이 있을 때만 시트에 한 줄을 덧붙이고 평소에는 이유를 설명하지 않는다
- **그날 이미 계획이 있으면 덮어쓸지 묻는다.** 날짜를 몰래 비켜가지 않는다.
  하루 계획은 최대 1개이므로(`CONTRACT.md`) `PATCH /plans/{id}`로 고쳐 쓴다
- 추가되면 시트를 닫고 버튼 자리를 `N월 N일 계획에 추가했어요.`로 바꾼다. 화면 이동 없음
- **GPS 거리 이력이 없으면 버튼을 감춘다.** 추천할 거리가 없는데 예약을 권할 수 없다

### `/analysis` 분석
- 날짜별 리포트 목록 (완주 여부·평균 리듬·**안정 구간**)
- 항목 탭 → 상세 (리포트 화면 재사용)
- 리듬·페이스 추이, 완주 횟수 흐름, 추천 목표 히스토리
- 삭제는 카드를 왼쪽으로 밀거나, 살짝 밀어 드러난 `삭제` 버튼으로 한다. 확인 후 지운다
- **지울 때 카드 높이를 접고 나서 목록을 갱신한다.** 밀려나 안 보여도 자리는 남아 있어서,
  접지 않으면 갱신되는 순간 아래 카드들이 위로 튄다
- 삭제가 실패하면 카드를 되돌린다. 서버에는 있는데 화면에서만 사라진 상태로 두지 않는다
- 삭제 시 캘린더·누적 러닝 데이가 함께 갱신된다
- API: `GET /runs`, `GET /runs/{id}`, `DELETE /runs/{id}`

### `/record` 기록
- 상단 캘린더 80%: 완료 ● / 수기 ○ / 예정 ◇
  **색만으로 구분하지 않고 라벨·형태를 함께 쓴다** (계획 / 완료 / 미완료 / 수기)
- **공휴일은 표시하지 않는다.** 러닝 기록과 무관한 정보이고, 음력 공휴일은 손으로 넣어야 해
  해가 바뀌면 조용히 틀린 값이 남는다
- 하단 프로필 20%: 누적 러닝 데이, 이번 달 활동일
- 날짜 탭 → 바텀시트: 계획 추가·수정·삭제·완료, 수기 기록 추가
- **수기 기록 입력 폼에서 목표를 묻지 않는다.** 날짜·시간(필수), 거리·메모(선택)만
  (`ERD.md` §5 — 사후 기록에는 목표라는 개념이 없다)
- 우상단 ⚙ → `/settings`
- API: `GET /calendar`, `POST|PATCH|DELETE /plans`, `POST /runs` (`source: MANUAL`)

### `/settings`
- 기본 정보 수정 / **신체 정보 수정·보완** / 목표 수정 / 음성·메트로놈 / 알림
- **기준 리듬 확인·재측정** (baseline 노출 지점 — `ENGINE.md` §2)
- 온보딩에서 **건너뛴 신체 정보를 여기서 채울 수 있다**. 비어 있으면 보완을 유도한다 (FR-028)
- 평균·권장치와의 비교는 어디에도 넣지 않는다 (`PRODUCT.md` §8-2)
- API: `GET|PATCH /users/me`
